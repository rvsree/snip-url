Built vs target, by concern

What the prototype does today, and what the target design changes

ConcernBuilt prototypeTarget design (not built)
LatencyRedirect: indexed lookup + one transaction; no load testRedis cache for hot links; click recording moved off the request path (Kafka)
ScalabilitySingle process, SQLiteStateless services behind a load balancer; Postgres with replicas
SQL vs NoSQLSQL: transactions, zero setupKey-value cache for redirects; SQL for links; OLAP store for analytics
Async processingSynchronous, in one transactionKafka topic link-clicks, analytics consumer
Failed transactionsRolled back (all or nothing); not storedDead-letter topic + failed_events table for retry and analysis
Rate limitingIn-memory, per direct IP, create onlyAt the API gateway with shared Redis counters; trusted proxy header
PrivacyIPs stored only as salted SHA-256 hashesSame + secret-managed salt + retention policy
SecurityURL validation; no link editing (phishing risk); agents cannot read secretsAuth on create and analytics; abuse and phishing checks
MonitoringWorkflow: audit log + metrics.py. App: access logMetrics, logs, traces, alerts, dashboards
