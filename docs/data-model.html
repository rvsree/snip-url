3 · Data dictionary

Every column, what it means, and where it comes from

short_links · one row per short link

ColumnType / ruleMeaning
codePK TEXTRandom 7-character base62 code, or a custom alias (3–30 letters, digits, hyphens; case-sensitive; reserved words rejected)
original_urlTEXT, not nullDestination; only http/https, up to 2048 characters
created_atTEXT, not nullCreation time (UTC)
is_custom_aliasINTEGER 0/1, default 01 if the user chose the code; 0 for random codes and for links created before S4 (not backfilled)
created_by_clientFK api_clients.id, null allowedWho created the link; NULL for links created before S4
last_clicked_atTEXT, null allowedTime of the latest redirect; NULL if never clicked

click_events · one row per redirect

ColumnType / ruleMeaning
idPK INTEGER autoincrementSurrogate key
codeFK short_links.code, not null, indexedWhich link was opened (index idx_click_events_code)
clicked_atTEXT, not nullRedirect time (UTC)
visitorFK link_visitors.id, null allowedWho clicked; NULL for clicks recorded before S4
user_agentTEXT, null allowedBrowser identification sent by the visitor
referrerTEXT, null allowedPage the visitor came from, if sent

link_visitors · one row per visitor (people who click)

ColumnType / ruleMeaning
idPK INTEGER autoincrementSurrogate key
ip_hashUQ TEXT, not nullSalted SHA-256 of the direct client IP (salt from IP_HASH_SALT); identifies a visitor without storing the IP
user_agentTEXT, default ''Latest browser identification seen
first_seen / last_seenTEXT, not nullFirst and latest visit (UTC)
visit_countINTEGER, default 0Total redirects by this visitor

api_clients · one row per API caller (people who create links)

ColumnType / ruleMeaning
idPK INTEGER autoincrementSurrogate key
ip_hashUQ TEXT, not nullSalted SHA-256 of the direct client IP
first_seen / last_seenTEXT, not nullFirst and latest call (UTC)
links_createdINTEGER, default 0Successful creates only (failed creates are not counted)
times_rate_limitedINTEGER, default 0How often this caller hit the limit (10 creates per 60 s); useful for spotting abuse

daily_link_stats · one row per link per UTC day

ColumnType / ruleMeaning
codePK FK short_links.codeWhich link
dayPK TEXT, not nullUTC calendar day (YYYY-MM-DD)
click_countINTEGER, default 0Redirects that day; updated in the same transaction as the click
unique_visitorsINTEGER, default 0Distinct visitors that day; feeds the analytics endpoints

4 · Keys, indexes and design notes

Why the model looks like this, and what would change at scale

ItemAs builtNote
Redirect lookupshort_links primary key on codeEvery redirect is a primary-key lookup: the fastest possible read
Clicks per linkIndex idx_click_events_codeSupports stats per link
One stat row per dayComposite PK (code, day)Database itself prevents duplicate daily rows
One row per visitor / clientUNIQUE on ip_hashAlso gives an index for the lookup on every request
Analytics readsFrom daily_link_stats, not raw clicksPre-aggregated, so analytics cost does not grow with click volume
ConsistencyClick, visitor, last_clicked_at and daily stat in one transactionRaw clicks and daily totals can never disagree
PrivacyOnly salted hashes of IPsUnique counts still work (same IP + same salt = same hash)
Not indexed (prototype)click_events.clicked_at, click_events.visitor, short_links.created_by_clientnote Not needed for current queries; add if queries by time, visitor or creator are added
Foreign keys in SQLiteDeclared in the schemanote SQLite enforces them only when PRAGMA foreign_keys=ON is set per connection; enabled: repo/db.py runs PRAGMA foreign_keys = ON in get_connection() for every connection
